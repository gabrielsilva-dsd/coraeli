# Usuários e Fluxos do Produto

## 1. Usuário criador

É a pessoa que deseja montar e entregar um presente digital.

### Necessidades

- criar algo bonito sem saber programar;
- entender rapidamente como usar a plataforma;
- visualizar o resultado antes da publicação;
- personalizar o presente;
- salvar e continuar depois;
- compartilhar com facilidade;
- confiar que suas fotos e mensagens estarão protegidas.

### Principais dificuldades

- não saber organizar textos e fotos;
- ter pouco tempo para criar a surpresa;
- acessar a plataforma principalmente pelo celular;
- não possuir experiência com ferramentas de edição;
- ter receio de pagar antes de conhecer o resultado.

## 2. Pessoa presenteada

É quem recebe o link ou escaneia o QR Code.

### Necessidades

- abrir o presente sem criar uma conta;
- ter uma experiência emocionante e fácil de entender;
- visualizar corretamente no celular;
- controlar a reprodução de músicas e vídeos;
- navegar sem lentidão;
- identificar quem criou o presente;
- não encontrar propagandas invasivas.

## 3. Administrador da plataforma

É a pessoa responsável por operar o produto.

### Responsabilidades futuras

- acompanhar usuários e páginas;
- verificar pagamentos;
- responder solicitações de suporte;
- moderar conteúdo denunciado;
- bloquear páginas que violem as regras;
- acompanhar armazenamento e desempenho;
- controlar temas e funcionalidades;
- visualizar métricas gerais sem expor conteúdo privado desnecessariamente.

## 4. Trabalho principal do produto

Quando uma pessoa desejar presentear alguém de maneira diferente, ela poderá criar uma experiência digital personalizada sem precisar contratar um desenvolvedor ou aprender ferramentas de edição.

## 5. Fluxo principal de criação

1. O usuário acessa a página inicial.
2. O usuário visualiza exemplos e entende o funcionamento.
3. O usuário seleciona **Criar presente**.
4. O usuário escolhe a ocasião.
5. O usuário escolhe um tema inicial.
6. O usuário informa os dados básicos.
7. O editor é aberto.
8. O usuário adiciona e reorganiza blocos.
9. O usuário envia fotos e adiciona uma música.
10. A prévia é atualizada em tempo real.
11. O rascunho é salvo.
12. O usuário revisa a versão para celular.
13. O sistema verifica se existem informações obrigatórias ausentes.
14. O usuário escolhe uma opção de publicação.
15. O pagamento é realizado, quando aplicável.
16. A página é publicada em um endereço exclusivo.
17. O sistema gera o QR Code.
18. O usuário recebe o link e o QR Code.
19. O presenteado acessa a experiência.
20. O criador pode acompanhar visitas e editar informações permitidas.

## 6. Fluxo de rascunho

1. O usuário inicia uma criação.
2. O sistema salva as alterações automaticamente.
3. O usuário fecha a plataforma.
4. Ao retornar, o rascunho aparece no painel.
5. O usuário continua do ponto em que parou.

Antes da criação de uma conta, um rascunho temporário poderá ser mantido no navegador. Para salvar permanentemente e acessar em outro dispositivo, será necessário criar uma conta.

## 7. Fluxo de compartilhamento

1. A página é publicada.
2. O sistema gera um link exclusivo.
3. O sistema cria um QR Code apontando para esse link.
4. O usuário pode copiar o link.
5. O usuário pode baixar o QR Code.
6. O presenteado abre o link ou escaneia o código.
7. A página verifica se está ativa e se possui senha.
8. O conteúdo é carregado de acordo com o tema escolhido.

## 8. Fluxo de página protegida

1. O presenteado acessa o link.
2. O sistema solicita a senha definida pelo criador.
3. Uma senha incorreta não libera o conteúdo.
4. Uma senha correta permite abrir o presente.
5. Tentativas repetidas deverão possuir limitação para evitar abuso.

A senha da página não será armazenada em texto puro.

## 9. Fluxo de expiração

1. O sistema identifica o prazo da publicação.
2. Enquanto estiver ativa, a página pode ser acessada normalmente.
3. Quando o prazo terminar, o conteúdo deixa de ficar disponível publicamente.
4. O criador recebe uma opção clara de renovação.
5. Os dados não deverão ser apagados imediatamente sem aviso.

As regras de retenção e exclusão serão definidas de forma transparente.

## 10. Fluxos de erro importantes

A plataforma deverá tratar:

- imagem incompatível;
- imagem maior que o limite;
- falha durante o upload;
- perda temporária de conexão;
- link de música inválido;
- rascunho não salvo;
- pagamento não aprovado;
- página inexistente;
- página expirada;
- senha incorreta;
- QR Code apontando para página indisponível;
- sessão expirada;
- tentativa de acessar dados de outro usuário.

## 11. Regras de experiência

- nenhuma alteração importante deverá ser perdida sem aviso;
- ações destrutivas deverão solicitar confirmação;
- mensagens de erro deverão explicar como resolver o problema;
- o usuário deverá saber se o rascunho está salvo;
- o editor deverá funcionar com toque, mouse e teclado;
- músicas não deverão começar de forma inesperada quando o navegador impedir reprodução automática;
- a página presenteada não exigirá cadastro;
- o criador somente poderá editar páginas pertencentes à própria conta;
- o sistema deverá oferecer uma forma de excluir conta e conteúdo.
